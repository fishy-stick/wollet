# 临时问题记录：Windows 桌面倒计时未弹出

用途：仅用于保存本次排查上下文。问题修复并完成验收后，随修复提交删除本文件；不作为长期开发计划或永久问题档案保留。

状态：2026-09-23 已定位，待修复；阻塞同步倒计时的真实安装环境验收。

现象：管理页面显示关机倒计时，但目标电脑没有弹出倒计时窗口。现场安装版本为 `1.1.0-dev.4+pipefix`，Wollet 服务以 `NT AUTHORITY\LocalService` 身份在会话 0 运行，已安装程序的 `--desktop` 进程在用户会话 1 运行，并非桌面进程未启动。

实测证据与代码路径：

- 对 `Wollet.ShutdownPlan.v1` 命名管道的只读探测可以建立连接，`GetNamedPipeServerProcessId` 成功取得后台服务进程 ID。
- 按桌面客户端现有校验方式调用 `OpenProcess(0x1000)`（`PROCESS_QUERY_LIMITED_INFORMATION`）失败，Windows 返回错误 5（拒绝访问），因此无法查询服务进程路径。
- `DesktopPlanContext.SendAsync`（`clients/windows/Wollet.Client/CountdownForm.cs`）在读取计划前检查服务会话与可执行文件路径；进程句柄无效时抛出“后台服务身份无效”，不会发送 `snapshot` 请求。
- `PollAsync` 捕获异常后只更新已有窗口的错误文案；第一次读取计划就失败时 `_form` 为空，错误不可见，后续轮询仍无法创建窗口。
- `DesktopCompatibilityReader` 使用相同的进程路径校验，也需要一并检查。网页通过服务端获取计划，不依赖本机桌面 IPC，因此网页倒计时可见不代表本地弹窗正常。

与已有修复的关系：`v1.1.0-dev.5` 的管道修复处理的是连接断开后未清理管道、导致后台服务以 `Pipe is broken` 异常退出的问题；它未修改上述身份校验，不能视为已解决桌面倒计时缺失。现场探测未发送关机指令，也未执行新的完整关机验收。

后续修复要求：

- 采用普通交互用户可完成的服务身份验证方式，同时保留对伪造管道服务端的防护；不得以删除身份校验或要求桌面进程常驻管理员权限作为修复。
- 区分服务未运行、管道连接失败和服务身份验证失败，在尚无倒计时窗口时也提供可见、可诊断的状态，避免静默重试掩盖问题。
- 在真实 `LocalService` 服务与非提权桌面进程组合下验收：收到计划后弹窗、两端剩余时间一致、本地取消与立即执行、网页取消后关闭窗口，以及服务重启后的恢复。
- 回归管道异常断开后的继续监听、会话权限限制及伪造服务端拒绝；覆盖包含 Runtime 和 framework-dependent 两种发行形式。执行关机验证应使用测试机或模拟关机实现。
