# Windows WPF 迁移记录

本文记录 WPF 迁移的架构、行为约束及验证结果。发布版本和附件以 [GitHub Releases](https://github.com/fishy-stick/wollet/releases) 为准。

## 范围与架构

按确认范围整体移除 WinForms，包括旧窗口、控件和 NotifyIcon 依赖，不保留双 UI 实现。支持目标为 Windows 10／11 x64；本轮仅在 Windows 11 验证，Windows 10 尚无设备验收记录。

- `Wollet.Client.Core`：协议、计划引擎、版本与能力规则，保持原有执行权威。
- `Wollet.Client.Application`：不依赖 WPF 的安装协调、管理窗口状态、倒计时状态及串行 IPC 控制。可独立测试并发、取消和生命周期。
- `Wollet.Client/Presentation`：WPF 窗口、资源样式、矢量进度动画、键盘操作，以及工作区定位和原生通知图标适配。
- 原有服务、凭据存储、升级替换和本地 IPC 适配仍由客户端宿主提供；没有修改通信协议或配对数据格式。

程序仍为单入口三种模式：服务、普通权限桌面提示、独立提权的安装管理。服务路径不初始化 WPF Application。桌面进程使用显式退出模式，关闭一次倒计时不会结束后续提示；升级停止标记取消并等待正在进行的 IPC 退出。

视觉采用浅色背景、深色正文和蓝色主要操作，危险操作用红色，支持系统高对比度资源。管理窗口可调整大小并滚动；倒计时保持不抢焦点、默认取消、Escape 取消。窗口绑定与动画在关闭后释放。

原来没有常驻托盘菜单，但有 IPC 连续失败三次时出现、恢复后移除的临时警告图标。本次通过 `Shell_NotifyIconW` 保留它，并处理 Explorer 重启；没有新增托盘产品功能。

## 行为与维护边界

- 关机仍由后台计划引擎执行，UI 动画不会触发关机。显示使用单调时间，同一计划修订不会因迟到快照延长；操作绑定原计划 ID／修订，不能误作用于替换计划。
- IPC 轮询不重叠，提交期间禁止重复操作；响应后按权威计划更新，超时不伪装成功。连续连接失败与恢复独立管理通知图标。
- 更新保留配对、同版修复、旧版／未知版本拦截、重新绑定和卸载沿用既有协调流程。刷新不会覆盖用户正在编辑的地址或 Token。
- 安装操作期间保护关闭，异步检查和进度回调带生命周期／操作代次保护，关闭后不再更新窗口。
- 不使用 WinForms 桥接、永久兼容层或产品内测试开关。窗口测试注入假的协调器和 IPC，不安装服务、不执行关机。

## 资源成本

迁移前后 Release 临时 UI 探针各运行三次，以下为中位数或近似值。旧版取首次 Paint，WPF 取 ContentRendered，计时从 UI 入口开始，不能等同于真实冷启动到屏幕可见的端到端延迟；探针不包含完整 IPC 轮询。这些数字用于揭示成本，不作为性能达标证明。

| 项目 | WinForms 基线 | WPF |
| --- | --- | --- |
| 首次显示事件 | 276 ms | 666 ms |
| 工作集 | 74 MiB | 124 MiB |
| 私有内存 | 26 MiB | 88 MiB |
| 5 秒进程 CPU 时间 | 344 ms | 453 ms |
| 含运行库单文件 | 112.3 MiB | 约 134.9 MiB |
| framework-dependent 单文件 | 1.77 MiB | 约 1.82 MiB |

WPF 的布局、矢量动画及高 DPI 实现带来可维护性收益，同时增加启动、内存和包体成本。按用户确认，本产品以一次性使用场景为主，不安排专项性能测试，也不设置性能发布门槛。上述已采集数据仅作迁移记录；高刷新率显示效果通过普通视觉验收检查。

## WPF 回归检查范围

以下列出界面迁移涉及的回归场景，两种发行形式均适用。既有安装、配对和关机功能已完成人工验收；本节用于说明检查范围，各次验证的实际覆盖见带日期的记录。

- 首次安装、UAC 入口、绑定并重连；旧版本升级复用 DPAPI 凭据，不产生重复设备。
- 同版修复、降级／未知版本拦截、配置缺失／损坏、更新失败恢复、卸载与重启删除。
- 真服务 IPC 倒计时、取消、立即执行、自然到期、断线恢复、连续计划；实际关机恰好一次。
- 锁屏、活动控制台切换、睡眠恢复及升级退出后的桌面提示恢复。
- 真实 100%／150%／200% DPI、混合 DPI 跨屏、高刷新率、系统高对比度与辅助技术。
- 临时警告图标显示、恢复移除与 Explorer 重启后的恢复。

2026-10-04 的迁移验证记录未覆盖 Windows 10、完整混合 DPI 跨屏及真实系统高对比度矩阵。

### 本机联合检查补充（2026-10-04）

额度恢复后完成沙箱外只读检查：

- 现有 1.1.0 Wollet 服务身份校验和 snapshot 请求成功，无活动关机计划。
- compatibility 请求成功，现有客户端／服务端均为 1.1.0，返回 compatible。
- 使用实际安装文件及本机验证构建比较，升级决策为 Update。
- 当前普通用户探针无法取得受保护的配对配置；File.Exists 在不可访问路径上可能返回 false，此探针的“配置缺失”不能证明实际配置缺失。该探针未覆盖提权管理窗口的配对读取与升级，后续实际升级检查见下文。
- 两种本机验证构建的单文件发行入口均完成 --desktop 冒烟验证，复用现有桌面互斥量，没有启动第二个桌面提示进程；该检查不等同于完整安装后的 UI 验收。
- 独立 STA 进程调用真实 Shell_NotifyIconW，注册与通知请求返回成功，三秒后释放并正常退出。未重启 Explorer，未逐帧验证通知视觉效果。
- 新增四个可重复的隔离集成场景：真实 Windows 命名管道、生产管道连接循环／响应写入、真实计划引擎、应用控制器和 WPF 窗口共同验证取消、立即执行、到期及系统执行失败。每次执行次数准确，取消后能够显示下一计划；电源控制使用记录替身，不调用真实关机 API。Windows 测试共 14 项通过。

### 实际升级检查补充（2026-10-04）

用户确认后，已从已安装的 1.1.0 连续更新至多个本机验证构建：每次安装文件哈希均与对应测试包一致，Windows Service 均重新进入 Running，桌面提示进程重新启动，临时停止标记已清理。提权管理窗口读取了原配对地址，显示服务已连接，且更新完成后版本决策为 Repair，证明升级未重写本地配对。服务端仍为 1.1.0，因此兼容提示显示版本不一致／功能受限；这是跨版本预期状态，不是更新故障。这些本机构建仅用于当时的本机验证。

该实际检查揭示完整构建哈希会在 600 宽主窗口折行并触发滚动条。当时的修复只在主窗口显示语义版本，并将默认窗口高度调整到 700，以容纳更新成功提示。该修复经过 91 项核心／状态测试、14 项 WPF 测试和无滚动条布局断言验证，并在本机实际升级成功提示状态下确认没有滚动条。

测试后现有服务仍在运行，桌面提示进程也已恢复；没有卸载、重新绑定或修改现有配对，未执行真实关机。本次检查未覆盖真实首次安装、DPAPI 复用、混合 DPI 跨屏、实际系统高对比度与电源场景。

### 客户端版本构建检查（2026-10-05）

客户端项目设置 `IncludeSourceRevisionInInformationalVersion=false`，关闭 .NET SDK 自动追加提交哈希。使用 `Version=1.2.0-dev.1` 和显式提交哈希构建通过；生成的 `AssemblyInformationalVersion` 与 Windows 文件 `ProductVersion` 均为 `1.2.0-dev.1`。两种发布配置均继承该规则。
